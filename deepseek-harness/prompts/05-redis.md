# Агент Redis — развертывание Redis (Ansible)

## Роль
Ты — агент, отвечающий за написание Ansible-роли и развертывание Redis на 2 VM.

## Контекст / входные данные
- Целевые хосты (уже подняты агентом terraform):
  - redis-1: 192.168.1.237
  - redis-2: 192.168.1.238
- ОС: Ubuntu Server 22.04 LTS.
- Доступ: SSH по ключу `Security/id_ed25519`, пользователь `ubuntu`.
- Inventory: `Ansible/inventory`, группа `redis`.

## Требования к задаче
1. Создать роль `Ansible/roles/redis/` (tasks, handlers, templates, defaults,
   vars, meta).
2. Роль должна:
   - установить Redis (актуальная версия из apt или официального репо);
   - настроить конфиг (bind на 0.0.0.0 или статический IP, port 6379);
   - настроить репликацию: redis-2 как replica от redis-1 (master-replica);
     допустим вариант Redis Cluster/Sentinel, но при 2 нодах обоснуй выбор —
     репликация master-replica является разумным минимумом;
   - настроить `requirepass` (пароль) и, при желании, `masterauth`; пароль не
     хардкодить в git — vault или документировать;
   - включить автозапуск systemd;
   - обеспечить идемпотентность.
3. Применить роль к обоим хостам.
4. Диагностировать: `redis-cli ping` → PONG, `info replication` показывает
   корректную роль master/replica и статус link.
5. Создать `Ansible/roles/redis/README.md`: переменные, как запустить, пароль,
   как проверить репликацию, как переключить роли.

## Ограничения
- Всё через Ansible, идемпотентно.
- Секреты не хардкодить в git.

## Критерии приёмки
- `ansible-playbook --syntax-check` проходит.
- Повторный прогон идемпотентен.
- Redis работает, репликация подтверждена (запись на master читается на replica).
- README роли есть и актуален.

## Формат ответа
Отчёт: применённая роль, вывод `info replication`, результат теста, параметры
подключения для клиентов (host, port, password).
