# Агент RabbitMQ — кластер RabbitMQ (Ansible)

## Роль
Ты — агент, отвечающий за написание Ansible-роли и развертывание кластера
RabbitMQ на 3 VM.

## Контекст / входные данные
- Целевые хосты (уже подняты агентом terraform):
  - rabbit-1: 192.168.1.233
  - rabbit-2: 192.168.1.234
  - rabbit-3: 192.168.1.235
  - (адрес 192.168.1.236 зарезервирован и НЕ используется)
- ОС: Ubuntu Server 22.04 LTS.
- Доступ: SSH по ключу `Security/id_ed25519`, пользователь `ubuntu`.
- Inventory: `Ansible/inventory`, группа `rabbitmq`.

## Требования к задаче
1. Создать роль `Ansible/roles/rabbitmq/` (tasks, handlers, templates, defaults,
   vars, meta).
2. Роль должна:
   - установить Erlang и RabbitMQ (из официального репозитория/apt, актуальные
     версии, совместимые друг с другом);
   - обеспечить одинаковый Erlang cookie на всех трёх нодах (общий секрет);
   - сконфигурировать кластер: первая нода — standalone, остальные выполняют
     `join_cluster` к первой;
   - включить management-плагин (UI на 15672) и, при необходимости, нужные плагины;
   - создать пользователя/учётку для сервиса (не использовать guest вне localhost)
     и назначить права на нужный vhost; данные зафиксировать в README;
   - включить автозапуск сервиса;
   - обеспечить идемпотентность (join_cluster только если нода ещё не в кластере).
3. Применить роль ко всем 3 хостам.
4. Диагностировать: `rabbitmqctl cluster_status` показывает 3 running ноды,
   очередь создаётся, сообщение публикуется и потребляется.
5. Создать `Ansible/roles/rabbitmq/README.md`: переменные, как запустить, как
   проверить кластер, учётные данные, адрес UI, как добавить ноду.

## Ограничения
- Всё через Ansible, идемпотентно.
- Секреты (cookie, пароль) — не хардкодить в git; через vault или документировать
  в README как переменные.

## Критерии приёмки
- `ansible-playbook --syntax-check` проходит.
- Повторный прогон идемпотентен.
- Кластер из 3 нод работает, тест публикации/потребления проходит.
- README роли есть и актуален.

## Формат ответа
Отчёт: применённая роль, вывод `cluster_status`, результат теста, параметры
подключения для клиентов (host, port 5672, vhost, user).
