# Агент Service — Java монолит на Spring Boot

## Роль
Ты — агент, отвечающий за разработку Java-монолита на Spring Boot, который
реализует сквозной event-driven pipeline через Kafka → RabbitMQ → Redis.

## Контекст / входные данные
- Стек: Java 17 (или 21), Spring Boot 3.x, Maven или Gradle (на выбор, обоснуй).
- Интеграции:
  - Kafka (KRaft): bootstrap `192.168.1.230:9092,192.168.1.231:9092,192.168.1.232:9092`
  - RabbitMQ: `192.168.1.233:5672` (кластер 233-235), учётка из README роли rabbitmq
  - Redis: `192.168.1.237:6379`, пароль из README роли redis
- Монолит запускается **локально** (не деплоится на VM).
- Каталог проекта: `Service/`.

## Требования к функциональности
Реализовать один эндпоинт:

`POST /start`

Тело запроса (JSON):
```json
{ "message": "Hello, pipeline!" }
```

Сквозной процесс обработки (строго в таком порядке):
1. Принять сообщение из тела POST.
2. Отправить его в Kafka-топик (например `input-topic`).
3. Прочитать его обратно из Kafka (consumer).
4. **Обогатить** сообщение информацией (например, добавить timestamp, метку
   этапа `kafka-processed`, id — на твоё усмотрение, но должно быть видно, что
   сообщение реально прошло через Kafka).
5. Переложить обогащённое сообщение в RabbitMQ (exchange/queue).
6. Прочитать его из RabbitMQ (listener/consumer).
7. **Обогатить** ещё раз (метка этапа `rabbitmq-processed` и т.п.).
8. Переложить в Redis (записать под ключом, например по message id).
9. Прочитать из Redis.
10. **Обогатить** финально (метка этапа `redis-processed`).
11. Вернуть в HTTP-ответе финальное сообщение (JSON) со всеми тремя этапами
    обогащения, чтобы было видно полный путь.

## Требования к реализации
1. Каталог `Service/` — полноценный Spring Boot проект.
2. Настроить `application.yml` с параметрами Kafka, RabbitMQ, Redis через
   переменные окружения (с дефолтами под адреса выше).
3. Использовать Spring Kafka (KafkaTemplate + @KafkaListener), Spring AMQP
   (RabbitTemplate + @RabbitListener), Spring Data Redis (StringRedisTemplate).
4. Сделать pipeline синхронным или асинхронным на твоё усмотрение, но HTTP-ответ
   должен возвращать финальное сообщение после прохождения всех этапов. Обоснуй
   выбранный подход (например, блокирующий вызов + CountDownLatch/CompletableFuture,
   либо outbox-стиль). Предпочтительно простое и надёжное решение.
5. Добавить тесты (хотя бы unit + интеграционный smoke с Testcontainers, если
   возможно; иначе задокументировать ручную проверку).
6. Проект должен собираться (`mvn package` / `gradle build`) и запускаться локально.
7. Создать `Service/README.md`: как собрать, как запустить, пример `curl`-запроса,
   описание архитектуры и этапов обогащения, требуемые внешние зависимости.

## Критерии приёмки
- Проект собирается без ошибок.
- `POST /start` локально проходит весь путь Kafka → RabbitMQ → Redis и возвращает
  финальное обогащённое сообщение со всеми тремя этапами.
- Конфигурация внешних систем параметризована (env/application.yml).
- README с инструкцией и примером запроса есть.

## Формат ответа
Отчёт: структура проекта, выбранные библиотеки, как запустить, результат
end-to-end проверки (реальный ответ эндпоинта).
