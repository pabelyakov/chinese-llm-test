# Агент Kafka — кластер Apache Kafka + KRaft (Ansible)

## Роль
Ты — агент, отвечающий за написание Ansible-роли и развертывание кластера
Apache Kafka в режиме KRaft (без ZooKeeper) на 3 VM.

## Контекст / входные данные
- Целевые хосты (уже подняты агентом terraform):
  - kafka-1: 192.168.1.230
  - kafka-2: 192.168.1.231
  - kafka-3: 192.168.1.232
- ОС: Ubuntu Server 22.04 LTS.
- Доступ: SSH по ключу `Security/id_ed25519`, пользователь `ubuntu`.
- Inventory уже заведён агентом terraform в `Ansible/inventory` (группа `kafka`).

## Требования к задаче
1. Создать роль `Ansible/roles/kafka/` (tasks, handlers, templates, defaults,
   vars, meta). При необходимости добавить общий `site.yml`/`playbook` для kafka.
2. Роль должна:
   - установить JDK (OpenJDK 17 или 21) и Apache Kafka (рекомендуется последняя
     стабильная версия, поддерживающая KRaft, например 3.x);
   - сконфигурировать KRaft-режим: сгенерировать cluster ID (один на кластер),
     сформатировать хранилище лога (`kafka-storage format`), настроить
     `controller.quorum.voters` для всех трёх нод;
   - назначить уникальный `node.id` и `broker.id` каждой ноде;
   - настроить listeners и advertised.listeners на статический IP ноды
     (PLAINTEXT 9092, controller 9093);
   - запустить Kafka как systemd-сервис, включить автозапуск;
   - обеспечить корректный порядок: форматирование storage — один раз, только
     на первой настройке.
3. Применить роль ко всем 3 хостам через `ansible-playbook`.
4. Диагностировать кластер: все брокеры в ISR, кластер видит 3 ноды, создание
   топика и отправка/чтение тестового сообщения проходит успешно.
5. Создать `Ansible/roles/kafka/README.md` с инструкцией: переменные, как запустить,
   как проверить состояние (`kafka-broker-api-versions` / `kafka-topics.sh`),
   как добавить/удалить ноду.

## Ограничения
- Все операции через Ansible (идемпотентно), никаких ручных ssh-команд вне плейбука.
- Пароли/секреты не хардкодить (использовать defaults/vault или документацию).

## Критерии приёмки
- `ansible-playbook --syntax-check` проходит.
- Повторный прогон роли идемпотентен (не ломает уже работающий кластер).
- Кластер из 3 брокеров KRaft работает: тест продюсер/консюмер проходит.
- README роли есть и актуален.

## Формат ответа
Отчёт: применённая роль, команды диагностики и их вывод, подтверждение работы
кластера, адрес для подключения клиентов (bootstrap servers).
