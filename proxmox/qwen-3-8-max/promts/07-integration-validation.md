## ЗАДАЧИ
1. Прогнать end-to-end: стартовать Service локально (env из секретов), выполнить несколько POST /start
   с разными payloads, убедиться что каждое сообщение прошло Kafka -> RabbitMQ -> Redis и вернулось
   обогащённым. Зафиксировать реальные запрос/ответ.
2. Проверить устойчивость: параллельные /start (несколько correlationId одновременно), поведение при
   таймауте, что происходит при недоступности одного узла Kafka/RabbitMQ/Redis (кратко, без разрушения
   кластера).
3. Health-срез кластеров: kafka-topics --describe (RF=3), rabbitmqctl cluster_status (3 узла),
   redis-cli INFO replication (replica online). Сохранить выводы.
4. Написать корневой README.md проекта: обзор архитектуры (ASCII/mermaid-схема пайплайна), IPAM,
   как всё поднять с нуля (порядок: Agent1..Agent6 / terraform -> ansible -> service), как запустить
   /start, где секреты, известные ограничения (D1, D2, ресурсы 2GB), траблшутинг.
5. Написать docs/RUNBOOK.md: типовые операции (перезапуск сервисов, добавление узла, ротация паролей,
   как диагностировать каждую подсистему: нужные команды journalctl/redis-cli/rabbitmqctl/kafka).
6. Собрать итоговый docs/VALIDATION.md: что проверено, статус, приложить логи/выводы, список рисков.

## DELIVERABLES
корневой README.md, docs/RUNBOOK.md, docs/VALIDATION.md, скрипт(ы) смоук-теста (опц.).

## ACCEPTANCE
- Минимум 3 успешных сквозных прогона /start с разными payloads (приложить вывод).
- Health всех трёх кластеров подтверждён выводами команд.
- README позволяет новому инженеру поднять систему с нуля без устных знаний.
- Ограничения (Redis 2 узла, RabbitMQ .236 резерв, 2GB тюнинг) явно задокументированы.
