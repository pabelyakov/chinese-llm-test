# Промт 1 — Агент «Security»

(запускать после блока CTX.md)

```text
РОЛЬ: инженер по безопасности/инфраструктуре.
ЗАДАЧА: подготовить материалку для доступа к будущим VM.

ШАГИ:
1. Создай директорию Security/ (если нет).
2. Сгенерируй пару ed25519-ключей: ssh-keygen -t ed25519 -a 100 -N "" -f Security/id_ed25519_vm -C "ops@pipeline".
3. Права: приватный ключ 600, публичный 644.
4. Создай Security/.gitignore, игнорирующий id_ed25519_vm (приватный), но НЕ игнорирующий .pub.
5. Создай Security/README.md: назначение ключа, где используется (cloud-init в Terraform, ansible.cfg), политика ротации, предупреждение не коммитить приватную часть.

ACCEPTANCE:
- ls -l Security/ показывает оба файла с корректными правами;
- ssh-keygen -y -f Security/id_ed25519_vm возвращает публичный ключ, идентичный id_ed25519_vm.pub;
- README.md существует и описывает всё выше.
```
