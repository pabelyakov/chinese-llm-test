# Промты суб-агентов для event-driven системы

Набор промтов для автономных агентов, которые с нуля строят локальную демонстрационную
event-driven систему: кластеры RabbitMQ / Kafka / Redis в Docker Compose + монолит
Java Spring Boot, прогоняющий сообщение по цепочке Kafka → RabbitMQ → Redis.

## Состав

| Файл | Агент | Назначение |
|---|---|---|
| `00_orchestrator.md` | Оркестратор | Координация агентов, конвенции, шлюзы приёмки, финальный отчёт |
| `01_infra_rabbitmq.md` | Инженер RabbitMQ | Кластер RabbitMQ из 3 нод в docker compose |
| `02_infra_kafka.md` | Инженер Kafka | Кластер Kafka из 3 нод (KRaft, без ZooKeeper) в docker compose |
| `03_infra_redis.md` | Инженер Redis | Кластер Redis на 2 логических нодах в docker compose |
| `04_java_monolith.md` | Java-разработчик | Монолит Spring Boot: POST /start → Kafka → RabbitMQ → Redis → HTTP-ответ |
| `05_e2e_verification.md` | Инженер внедрения/QA | Сквозной прогон, отказоустойчивость, диагностика, отчёт |
| `06_documentation.md` | Технический писатель | Итоговая документация, runbook, унификация README |

## Порядок использования

1. Запустить агента с промтом `00_orchestrator.md` (system prompt).
2. Оркестратор последовательно делегирует работу суб-агентам в порядке
   `01 → 02 → 03 → 04 → 05 → 06` (инфраструктурные агенты — строго по одному,
   они пишут в общий `docker-compose.yml`). Каждому суб-агенту передаются:
   - промт соответствующего файла целиком;
   - блок конвенций из `00_orchestrator.md`;
   - текущий статус проекта (что уже сделано, актуальные адреса/порты/имена);
   - конкретное задание и критерии приёмки.
3. После каждого этапа оркестратор проверяет шлюз приёмки (см. `00_orchestrator.md`).

## Общие правила для всех агентов

- Работай автономно: пиши файлы, запускай команды, диагностируй и исправляй самостоятельно.
- Минимум 3 самостоятельные попытки исправить проблему, прежде чем эскалировать.
- Ничего не коммить в git и не публикуй наружу.
- Все артефакты — только внутри `Docker/`, `Service/` или корня проекта.
- Версии ПО фиксируй, `latest` не использовать.

## Примечание

Промты самодостаточны: конвенции продублированы в каждом файле. При расхождении
приоритет у значений, переданных оркестратором вместе с заданием.

Инфраструктура разворачивается docker compose; Terraform в проекте не используется
(локальная среда). При необходимости промт terraform-агента можно добавить отдельно.
